## Summary

T0.3 **passes** the critical license bar for this pack. The builder uses an **allowlist schema** that never extracts `query_code` / `q_code`, `dic_ref` (Heisig/Halpern/etc.), or any audio source. The shipped pack and manifest claim only KANJIDIC2 under CC BY-SA 4.0 with correct attribution and an explicit SKIP/misclass omission note. Binary scan of `packs/kanji-v1.sqlite` found **no** `qc_type`, `skip_misclass`, `heisig`, `forvo`, `halpern`, `query_code`, or `dic_ref` strings.

Residual gaps are **control hardening**, not an active SKIP/Heisig/Forvo leak: the pipeline assertion is marker-string weak (would miss bare SKIP code values if a future column were added), and the builder does not verify the cached input against `sources.lock.json` sha256 before packing.

**Verdict:** **PASS with findings** (no Critical/High license violations in T0.3 output; Medium hardening items before treating the control as airtight).

## What the builder does (security-relevant)

### Allowlist extraction (`build-kanji-pack.ts`)

Parsed fields only:

- `literal`, UCS `codepoint`
- radicals `classical` / `nelson_c`
- `grade`, `stroke_count`(+alt), `freq`, legacy `jlpt`
- `ja_on` / `ja_kun` readings, EN meanings, `nanori`

**Not parsed at all:** entire `query_code` tree (SKIP, misclass, four_corner, …), entire `dic_ref` tree (Heisig, Halpern, Nelson indices, …).

The “STRIP SKIP / misclass” block (lines 153–162) only **counts** `qc_type="skip"|"misclass"` via regex; it does not need to mutate XML because no later step reads those nodes. Real safety is **non-extraction**, not post-hoc deletion.

### Output schema

```sql
CREATE TABLE kanji (
  id, literal, codepoint, radical_classical, radical_nelson,
  grade, stroke_count, stroke_count_alt, freq, jlpt_legacy,
  on_readings, kun_readings, meanings, nanori
);
```

No `skip*`, `misclass*`, `heisig*`, `dic_ref*`, or `query_code*` columns.

### Pipeline assertion (lines 255–274)

After insert, every row’s `on_readings|kun_readings|meanings|nanori` is checked for:

- `qc_type="skip"`
- `qc_type="misclass"`
- `skip_misclass`

Build aborts on match. Legitimate English glosses containing the word “skip” (e.g. 飛 “skip (pages)”) are correctly allowed — the earlier naive `includes('skip')` assertion was a false-positive bug fixed in this branch.

## Issues

### 1. Assertion would miss bare SKIP *values* if schema grew a skip column
**File:** `scripts/build-packs/build-kanji-pack.ts` (lines 255–274)  
**Severity:** Medium  
**Concern:** The control required by `DATA-SOURCES.md` §6 (“fail the build if a SKIP field survives”) only searches four JSON text columns for **XML attribute marker strings**. Real SKIP payloads look like `1-4-3` / `2-3-7` inside `<q_code qc_type="skip">…</q_code>`. If a later change added e.g. `skip_code TEXT` and stored those values, the current assertion would still pass while the pack redistributed Halpern SKIP data — a direct license violation (permission + encryption + non-redistribution terms).

Today’s allowlist path makes this latent, not active. The assertion is not a strong independent backstop.

**Suggestion:**

1. Assert schema deny-list: fail if any column name matches `/(skip|misclass|heisig|dic_ref|query_code|q_code|forvo)/i`.
2. Scan **all** column values (or the whole DB file bytes) for `qc_type="skip"`, `skip_misclass`, `dr_type="heisig"`.
3. Keep allowlist as primary defense; treat assertion as regression tripwire for schema + blob leaks.
4. Optional: require `skippedBadQc > 0` on a full KANJIDIC2 input so a silently truncated source without query_code blocks is noticed.

### 2. Builder does not verify cache input against `sources.lock.json`
**File:** `scripts/build-packs/build-kanji-pack.ts` (lines 26–29, 345–352)  
**Severity:** Medium  
**Concern:** Input path is hardcoded to `scripts/build-packs/.cache/kanjidic2-2026-07-25.gz`. There is no read of `sources.lock.json`, no sha256 compare to `79074f59…`, and no fail-closed on mismatch. A wrong, stale, or tampered cache file still produces a pack with a clean-looking manifest. That weakens the §11 reproducibility / “fail if license or source integrity drifts” posture and makes supply-chain mistakes harder to catch before ship.

Not license laundering by itself, but it is how a bad source could be packed under a good attribution story.

**Suggestion:** At build start:

```ts
const lock = JSON.parse(fs.readFileSync('scripts/build-packs/sources.lock.json', 'utf8'));
const expected = lock.sources.kanjidic2;
// resolve path from lock pinned id; sha256(file) === expected.sha256 or exit 1
// refuse if expected.license is missing / not CC BY-SA 4.0
```

Record the **source** sha256 in the pack manifest `sources[]` entry (salvage manifest had this; current T0.3 manifest dropped it).

### 3. Assertion scope is narrower than the full row
**File:** `scripts/build-packs/build-kanji-pack.ts` (lines 258–265)  
**Severity:** Low  
**Concern:** Only `on_readings`, `kun_readings`, `meanings`, `nanori` are concatenated for the leak check. Other columns are not scanned. With the current schema this is low risk (those columns are typed numbers/codepoints/literals), but a future TEXT column would be unchecked unless someone remembers to extend the blob.

**Suggestion:** Fold into Issue 1 — scan all text affinity columns or the sqlite file bytes once.

### 4. “Strip” wording overstates the mechanism
**File:** `scripts/build-packs/build-kanji-pack.ts` (header + lines 153–162, 354)  
**Severity:** Low (documentation / reviewability)  
**Concern:** Logs say “stripped N skip/misclass q_codes” but values are never loaded into the entry object. Reviewers may believe deletion is the control and then “optimize away” the unused loop or weaken the assertion.

**Suggestion:** Rename to “encountered and omitted (never extracted)” in comments and log lines; keep the counter as proof the source still contains SKIP blocks to omit.

### 5. Manifest source URL is plain HTTP
**File:** `packs/kanji-v1.manifest.json` (line 14); builder lines 325–331  
**Severity:** Low (inherits T0.1)  
**Concern:** EDRDG URL is `http://…`. Integrity for *this* build depends on lockfile + cache, but the published manifest points consumers at cleartext fetch. Prefer `https://` if EDRDG serves it (already noted in PHASE0-HANDOFF T0.1 findings).

**Suggestion:** Use HTTPS in lock + manifest when available; still pin sha256.

## License laundering assessment

**No laundering found.**

- Downstream license equals upstream (CC BY-SA 4.0), not a more permissive rebadge.
- ShareAlike preserved via `LICENSE-DATA` + pack manifest.
- Restricted subfields (SKIP, and by non-extraction Heisig indices) are **omitted**, not re-licensed as original KanjiForge data.
- Attribution identifies EDRDG and states modification (DB conversion + field omission).
- Pack does not mix KanjiVG (CC BY-SA 3.0) or other packs into this blob (avoids §3.3 single-header ambiguity).
