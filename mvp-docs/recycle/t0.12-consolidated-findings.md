## MUST FIX (severity-ranked)

### 1. CRITICAL — dirty-rect backing buffer never resized
- **Where:** `canvas-renderer.ts` `createRenderer()` builds `backingBuffer` from `canvas.width`/`height` at call time; `tile-wall.tsx` calls it *before* `applySize()`.
- **Bug:** Buffer stays at browser default 300×150 forever. Dirty-rect pan only blits a tiny patch; rest of wall goes stale/blank after pan+zoom.
- **Fix:** Inside `applySize()` (or equivalent size path), whenever canvas CSS/device size changes, resize or recreate `backingBuffer`/`backingCtx` to match `canvas.width`×`canvas.height` **before** any subsequent render. Also reset any dirty-rect state that assumes old dimensions.

### 2. HIGH — belt-rank colors invisible at medium zoom (28–60px) — default band
- **Where:** `buildGlyphAtlas` + `renderMediumZoom` in `canvas-renderer.ts`.
- **Bugs:**
  (a) Atlas rebuild condition is dead code — never fires in the 28–60px band; atlas built once, never refreshes on zoom-band change or theme change.
  (b) Atlas fills entire cell opaquely with level-0 color; `renderMediumZoom` draws correct per-tile level color then **overdraws** with atlas cell (baked level-0 bg) → all tiles sample as level-0 `(217,210,195)`.
- **Fix:** Atlas glyphs must be drawn on **transparent** (or color-key) background so per-tile level fill shows through; OR atlas stores glyph-only and level fill is separate. Rebuild atlas when: entering medium band, zoom crosses atlas cell-size threshold, or theme/CSS token colors change. Verify with pixel samples at tile corners across different levels at ~40px/tile.

### 3. HIGH — dirty-rect size guard mixes CSS px vs device px
- **Where:** pan delta accumulation vs `canvas.width`/`height` comparison.
- **Bug:** `panDeltaX`/`Y` in CSS pixels; canvas dimensions are device pixels (DPR-scaled). On DPR>1, guard is too permissive → large pans take expensive dirty-rect path.
- **Fix:** Compare in the same space (multiply deltas by DPR, or compare against CSS width/height). Fallback to full repaint when |delta| exceeds threshold in consistent units.

### 4. HIGH (perf) — near-threshold dirty-rect more expensive than full repaint
- Dirty path does: full-canvas blit + strip redraw (grows with delta) + full copy-back = 3 passes vs full repaint’s 1.
- **Fix:** Tighten fallback threshold and/or skip the double full-canvas copy when strip coverage exceeds ~30–40% of canvas; prefer full repaint. Measure that large pans don’t multi-second hang.

### 5. MEDIUM — no rAF coalescing
- Every wheel/pointermove synchronously calls render; bursts of 10–20 events stack work and poison FPS overlay.
- **Fix:** Coalesce input into one `requestAnimationFrame` tick; accumulate pan/zoom deltas; single render per frame. FPS overlay should measure real frame cost, not burst sum.

### 6. MEDIUM — architecture: glyph atlas rebuild dead code
- Covered by #2; ensure rebuild conditions are live and tested.

### 7. MEDIUM — DOM mode hand-rolls innerHTML + addEventListener
- **Where:** `renderDOMGrid` in `tile-wall.tsx`.
- **Fix:** Ordinary React `.map()` JSX + `onClick` (not a per-frame hot path).

### 8. MEDIUM — FpsOverlay uses `document.querySelector('canvas')`
- **Fix:** Pass canvas element (or ref) as prop from `TileWall`.

### 9. MEDIUM — screen-reader detection is dead
- **Where:** `src/app/prototype/tiles/page.tsx` checks `'ScreenReaderAnnounce' in window` and `role="application"` on body — never true.
- **Fix:** Remove dead branch; keep working `prefers-reduced-motion` + manual “Switch to list view” button. Be honest in comments/UI about what’s implemented.

### 10. LOW — move prototype out of `src/components/`
- `src/components/tile-wall/` collides with ARCHITECTURE.md tree (`ui/`/`features/` only).
- **Fix:** Move to `src/prototype/tile-wall/` (update imports/route). Prototype-only; don’t invent a new top-level convention for production code.

### 11. LOW — atlas not invalidated on theme change
- Covered by #2 rebuild triggers.

### 12. LOW — reduced-motion only checked once at mount
- Re-check on `matchMedia` change listener, or document as prototype limitation if intentionally static.

### 13. LOW — minor per-frame allocations
- Avoid obvious per-frame object/array alloc in hot render path if cheap to fix while touching the file.
