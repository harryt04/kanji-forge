# Correctness & Logic Review

**Scope:** T0.3 KANJIDIC2 → kanji pack ETL  
**Worktree:** `t0.3-kanji-etl`  
**Focus:** `scripts/build-packs/build-kanji-pack.ts`, `packs/kanji-v1.manifest.json`, `mvp-docs/t0.3-done-check.md`  
**Specs:** `DATA-SOURCES.md` §2.1 §6 §11.1, `ARCHITECTURE.md` §4.1, `ORCHESTRATION.md` T0.3  

## Summary

The ETL correctly extracts the §2.1 field set (literal, UCS codepoint, classical/Nelson radicals, grade, primary+alt strokes, freq, legacy JLPT, ja_on/ja_kun with `.`/`-` okurigana markers, English meanings, nanori) into a SQLite pack whose schema matches the intended shape. Spot-check rows (日/本/語/未/末) match upstream KANJIDIC2; EN-only gloss filtering and non-extraction of `query_code` mean SKIP data does not currently land in the pack. The critical gaps are a **non-functional SKIP pipeline assertion** (license gate is effectively a no-op), **no lockfile/SHA verification of the input**, and a few brittle parse/edge-case holes. No evidence of systematic readings/meanings corruption on the current pinned dump.

## Severity-ranked issues

### 1. HIGH — SKIP/misclass assertion cannot detect real SKIP leakage
**File**: `scripts/build-packs/build-kanji-pack.ts` (lines 255–275)  
**Concern**: The “CRITICAL PIPELINE ASSERTION” only scans `on_readings`, `kun_readings`, `meanings`, and `nanori` for the literal substrings `qc_type="skip"`, `qc_type="misclass"`, and `skip_misclass`. Those strings are XML attribute markup and will never appear in JSON arrays of kana/English glosses under the current extractor. Meanwhile actual SKIP *values* (e.g. `1-4-3`, `3-3-1`) are never checked, and non-selected columns are never inspected.

**Failure scenario**: A later change that adds something like `skip_code TEXT` / `query_codes TEXT` and copies `<q_code qc_type="skip">…` values into the pack would still pass this assertion and ship Halpern SKIP data — exactly the `DATA-SOURCES.md` §6 / T0.3 hard fail condition. The done-check “assertion passed” is therefore false confidence for the license gate.

**Suggestion**: Assert at schema + content level, e.g.:

```ts
// 1) No skip/misclass columns
const cols = db.prepare(`PRAGMA table_info(kanji)`).all() as { name: string }[];
for (const c of cols) {
  if (/skip|misclass/i.test(c.name)) {
    throw new Error(`SKIP-related column present: ${c.name}`);
  }
}
// 2) No raw qc markup anywhere in row text (SELECT * / every TEXT col)
// 3) Optionally: refuse any stored value matching SKIP pattern only if you ever store query codes
```

Also drop the misleading “stripped at parse time” counter as proof of strip — omission-by-never-extracting is fine, but the assertion must catch *storage*, not XML attribute strings in gloss blobs.

### 2. MEDIUM — Build does not verify input against `sources.lock.json`
**File**: `scripts/build-packs/build-kanji-pack.ts` (lines 26–29, 345–349)  
**Concern**: Source path is hardcoded to `scripts/build-packs/.cache/kanjidic2-2026-07-25.gz`. There is no SHA-256 check against `sources.lock.json` (`kanjidic2.sha256 = 79074f59…`). `DATA-SOURCES.md` §11 requires reproducible, checksum-gated builds.

**Failure scenario**: A corrupted, partially-downloaded, or manually replaced cache file still builds a pack with a fresh output SHA and a green done-check. Pack contents silently diverge from the locked upstream pin; CI “reproducible from lock” is broken.

**Suggestion**: Resolve path + expected hash from the lockfile; `sha256(file) === lock.sources.kanjidic2.sha256` or abort before parse.

---

### 3. MEDIUM — Hardcoded dated cache filename will break on lock refresh
**File**: `scripts/build-packs/build-kanji-pack.ts` (line 28)  
**Concern**: Filename embeds `2026-07-25`. When T0.1 refresh updates the pin/date, this builder keeps looking for the old name even if the lock and cache are current under a new name.

**Failure scenario**: `fetch-sources` updates lock + cache → `build:kanji` exits “source not found” or builds an older leftover gz still named with the old date.

**Suggestion**: Derive cache path from lock `pinned` / recorded filename, or scan cache for the lock’s sha256.

---

### 4. MEDIUM — Failed assertion leaves a pack file on disk
**File**: `scripts/build-packs/build-kanji-pack.ts` (lines 186–188, 253–275, 302–305)  
**Concern**: `OUTPUT_DB` is unlinked only at the start of a successful rebuild path. If the post-insert assertion throws, `catch` closes the DB but does not delete `packs/kanji-v1.sqlite`. Manifest is not rewritten, so a prior good manifest can pair with a new bad DB (or a first-run failure leaves an unmanifested DB).

**Failure scenario**: Operator or CI treats “file exists under packs/” as success after a red build; app or later task consumes a pack that failed the SKIP gate.

**Suggestion**: On any failure after `OUTPUT_DB` is created, `unlinkSync(OUTPUT_DB)` (and optionally the manifest) in `finally`/catch before rethrow.

---

### 5. LOW — Reading regex rejects DTD-legal extra attributes
**File**: `scripts/build-packs/build-kanji-pack.ts` (lines 125–131)  
**Concern**:

```ts
/<reading r_type="([^"]+)">([^<]+)<\/reading>/g
```

requires `>` immediately after `r_type="…"`. KANJIDIC2 DTD allows `on_type` and `r_status` on `ja_on` / `ja_kun` (e.g. `<reading r_type="ja_on" on_type="kan" r_status="jy">イチ</reading>`).

**Current data:** Grep of the pinned KANJIDIC2 dump shows **no** `on_type=` / `r_status=` usage today, so spot-checks (日/語 okurigana etc.) match. This is latent data-loss if upstream reintroduces those attrs.

**Suggestion**:

```ts
/<reading\b([^>]*)>([^<]+)<\/reading>/g
// then parse r_type from the attr blob
```

---

### 6. LOW — Silent drop of characters missing `<literal>` or UCS codepoint
**File**: `scripts/build-packs/build-kanji-pack.ts` (lines 75–82)  
**Concern**: `continue` with no counter when literal or `cp_type="ucs"` is missing. A malformed/truncated XML block or unexpected codepoint layout reduces `kanjiCount` without explanation; the only guard is the loose “~13k ±5%” done-check, which can still pass after dropping hundreds of entries.

**Suggestion**: Increment `skippedNoLiteral` / `skippedNoUcs` and fail the build if either is non-zero (or if count moves >5% vs expected baseline).

---

### 7. LOW — Manifest `sources[]` omits lock pin metadata
**File**: `scripts/build-packs/build-kanji-pack.ts` (lines 325–332); `packs/kanji-v1.manifest.json`  
**Concern**: §11.1 requires self-describing packs. Manifest has `id/name/license/url` but not the locked `sha256` / `pinned` date from `sources.lock.json`. Weaker provenance for audits and “same lock → same pack” debugging.

**Suggestion**: Copy `sha256` + `pinned` (and optionally `licenseHash`) from the lock into each `sources[]` entry when writing the manifest.

## What looks correct (no issue)

| Area | Assessment |
|------|------------|
| **§2.1 field set** | Schema covers literal, codepoint (lowercased hex), classical + nelson radicals, grade, stroke primary + alt JSON, freq, `jlpt_legacy`, on/kun/nanori, EN meanings. |
| **Okurigana markers** | Source `かた.る`, `-び`, `ひと-` preserved as-is (verified against KANJIDIC2 for 語/日/一). |
| **EN meanings only** | Unmarked + `m_lang="en"` kept; `fr`/`es`/`pt` excluded. 飛 retains legitimate gloss `skip (pages)`. |
| **SKIP not stored** | `query_code` / `q_code` never mapped into columns; no skip/misclass columns in schema. Primary protection is omission (works today). |
| **Alt strokes** | Multiple `<stroke_count>` → first primary, rest `stroke_count_alt` JSON (matches DTD “first accepted, rest miscounts”). |
| **Nanori** | Collected outside `rmgroup` from whole character block (matches DTD). |
| **Count / size** | 13108 entries, ~1.88 MB — within expected KANJIDIC2 order and under ~4 MB budget. |
| **Manifest required keys** | `id`, `version`, `schemaVersion`, `sha256`, `sizeBytes`, `license`, `attribution`, `sources[]` present. |

## Recommended fix order

1. Rewrite SKIP assertion so it can fail for real leakage (schema + full-row scan).  
2. Verify input gz SHA against `sources.lock.json`; resolve path from lock.  
3. Delete output DB on failed build.  
4. Harden reading-tag regex for optional attributes.  
5. Count/fail on skipped characters; enrich manifest source pin metadata.

## Verdict

**Conditional pass on data fidelity for the current pinned dump; fail the license/pipeline gate as implemented.** Readings/meanings/okurigana look right and SKIP is absent today by non-extraction, but T0.3’s required “fail the build if SKIP survives” assertion does not actually enforce that requirement.
