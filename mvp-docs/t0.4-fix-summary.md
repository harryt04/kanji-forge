# T0.4 Correctness Fixes Summary

## Issues addressed

### HIGH — Decode JMdict XML entities in POS/misc/gloss/form text
- **File**: `scripts/build-packs/build-words-core-pack.ts`
- **What changed**: Added `decodeJmdictEntities()` (handles `&name;` → name for JMdict DTD tags like n/uk/ateji, plus `&amp;`→`&`, `&lt;` etc, and `&#...;` numeric). Applied decode to every captured text value in parser (keb/reb/*_inf/*_pri/restr/pos/misc/field/dial/stag*/gloss.text).
- **Why**: Fixes root cause of raw `&n;` etc being stored in JSON BLOB, forms table, and FTS index (non-validating regex parser). Matches requirement to expand DOCTYPE entities before storage. Samples now show decoded e.g. `["pn"]` / `["uk"]` not `&pn;` / `&uk;`.

### MEDIUM — Verify input gz sha256 against sources.lock.json; no hardcode date path
- **File**: `scripts/build-packs/build-words-core-pack.ts`
- **What changed**: Removed hardcoded `jmdict-2026-07-25.gz` path. Added `resolveAndVerifyJmdictPath()` that reads `sources.lock.json`, derives filename from `id-pinned+ext` (using url for ext), checks file exists, computes sha256 of the .gz and asserts == lock entry (fail closed with clear error).
- **Why**: Prevents silent use of wrong/corrupt/mismatched cache file or stale hardcoded date after re-fetch. "Fail closed" per DATA-SOURCES. Build now logs `✓ Verified jmdict input ... against sources.lock.json`.

### MEDIUM — Atomic output (temp sqlite + rename; manifest only on success; cleanup on fail)
- **File**: `scripts/build-packs/build-words-core-pack.ts`
- **What changed**: Introduced `OUTPUT_DB_TMP` and `OUTPUT_MANIFEST_TMP`. Build now opens/writes to `.tmp`, renames to final only after `db.close()`. Manifest write also to `.tmp` then rename. Main catch block unlinks any `.tmp` on error (no partial DB + stale manifest left). Removed early unlink of final DB.
- **Why**: Interrupted build no longer leaves corrupt DB with out-of-date manifest (hash mismatch risk for consumers). Rename is atomic on POSIX. Manifest only published after full success.

### MEDIUM — Note compressed size in done-check (gzip)
- **File**: `scripts/build-packs/build-words-core-pack.ts` + `mvp-docs/t0.4-done-check.md`
- **What changed**: In `writeManifest`, compute `zlib.gzipSync(dbContent).length`, add `compressedSizeBytes` / `compressedSizeMB` to manifest, log it. Updated done-check with actual 7.18 MB gzip, raw size, honest note that >6 MB budget (Brotli may land later).
- **Why**: Makes the ~6 MB compressed budget verifiable in artifacts + logs (was only aspirational before). Rebuild confirmed gzip 7.18 MB.
