# C2 detail recovery investigation

- Symptom: `/detail` could leave users on `Loading detail…` with `aria-busy="true"` when no ref was selected or a requested ref could not resolve.
- Root cause: `DetailScreen` only loaded the deck when `contentRef` was truthy, and its final render branch collapsed loading, no selection, and unresolved content into one busy state. Missing pack records were also surfaced through a generic error path without the required recovery link.
- Fix: load the deck independently, add an explicit `notFound` state for unresolved kanji/word/name records, and render separate loading, no-card-selected, and not-found branches. The not-found branch links to `/browse`.
- Evidence: the focused detail suite passes 16 tests; mutation testing failed when the not-found state was disabled; `npm run ci` passed with 568 unit tests, 18 active E2E passes, 54 auth-dependent E2E skips, and all pack checks.
